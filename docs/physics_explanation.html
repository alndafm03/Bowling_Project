دالة احتكاك الممر (μ(z))

الدالة laneFrictionAt(z) تُعيد معامل الاحتكاك عند أي نقطة على الممر بشكل ناعم:

إذا d ≤ 8m → μ = 0.03 (زيتي) إذا d ≥ 12m → μ = 0.15 (جاف) بينهما → smoothstep من 0.03 إلى 0.15 حيث d = -z (المسافة من خط الفاول) 
export function laneFrictionAt(z) {
  const d = -z;  // المسافة من خط الفاول، موجبة دائماً
  if (d <= oilEnd)    return oil;
  if (d >= dryStart)  return dry;
  return oil + (dry - oil) * smoothstep(oilEnd, dryStart, d);
}
لماذا smoothstep وليس قفزة مفاجئة؟ لأن الانتقال المفاجئ في الاحتكاك يسبب اهتزازات رقمية في المحاكاة. الانتقال الناعم يُعطي سلوكاً أكثر واقعية ومستقراً.

2. RigidBody.js — الجسم الصلب

src/physics/RigidBody.js

هذا الكلاس يُمثّل أي جسم فيزيائي في العالم: الكرة، كل دبوس، والأرضية (جسم ثابت invMass=0).

الحالة (State) — ما يُخزَّن في كل جسم

الخاصيةالنوعالمعنى
positionVector3موضع مركز الكتلة في الفضاء
quaternionQuaternionالاتجاه (دوران ثلاثي الأبعاد)
velocityVector3السرعة الخطية (m/s)
angularVelocityVector3السرعة الزاوية (rad/s)
invMassnumberمعكوس الكتلة (0 = جسم ثابت)
invInertiaWorldMatrix3معكوس تنسور القصور الكلي (عالمي)

عزم القصور (Inertia Tensor)

الكرة الصلبة المتجانسة: I = (2/5) × m × R²

الاسطوانة (الدبوس) لها تنسور غير متماثل:

setCylinderInertia(mass, radius, height) {
  const Iaxis  = 0.5 * mass * radius * radius;  // حول المحور الرأسي (Y)
  const Itrans = (1/12) * mass * (3*radius² + height²);  // حول X,Z
  // هذا هو سبب سقوط الدبوس بشكل واقعي — مقاومة مختلفة في اتجاهات مختلفة
}
لماذا نُعيد حساب invInertiaWorld كل خطوة؟ لأن تنسور القصور يتغير مع دوران الجسم. للكرة (متماثلة) لا يتغير، لكن للدبوس يجب تحديثه دائماً: I⁻¹_world = R × I⁻¹_body × Rᵀ

تطبيق النبضة (applyImpulse)

هذه أهم دالة في المشروع — تُطبّق قوة آنية (نبضة) على جسم:

applyImpulse(J, worldPoint) {
  // تغيير السرعة الخطية: Δv = J / m
  this.velocity.addScaledVector(J, this.invMass);

  // تغيير السرعة الزاوية: Δω = I⁻¹ × (r × J)
  // r = نقطة التطبيق − مركز الكتلة
  r.subVectors(worldPoint, this.position);
  Δω = (r × J) × invInertiaWorld;
  this.angularVelocity.add(Δω);
}

نظام النوم (Sleeping)

الأجسام الساكنة تُوقَف تلقائياً لتوفير الحسابات:

updateSleep(dt) {
  if (speed < sleepLinear && angSpeed < sleepAngular) {
    sleepTimer += dt;
    if (sleepTimer > 0.4s) this.sleep(); // ينام بعد 0.4 ثانية هدوء
  } else {
    sleepTimer = 0; // أي حركة تُصفّر المؤقت
  }
}

3. Integrator.js — معادلات التكامل

src/physics/Integrator.js

التكامل يعني: كيف نُحوّل السرعة إلى موضع، والسرعة الزاوية إلى دوران.

لماذا Euler شبه الضمني وليس RK4؟

المعيارRK4Euler شبه الضمني
الاستقرار مع الاصطدامات❌ يمكن أن ينفجر✅ مستقر دائماً
التوافق مع النبضات❌ لا يتوافق✅ متوافق تماماً
حفظ الطاقة~جيد✅ ممتاز (Symplectic)
تكلفة الحساب4 تقييمات/خطوة1 تقييم/خطوة
تحذير: كل محركات الفيزياء التجارية (Unity، Unreal، Bullet) تستخدم Euler شبه الضمني مع خطوة زمنية ثابتة لنفس السبب — لا تُغيّر هذا الملف إلا إذا كنت متأكداً تماماً مما تفعل.

معادلات التكامل

v ← v + (F/m) × Δt [الخطوة 1: القوى الخارجية] [ حل النبضات يُعدّل v و ω مباشرة ] x ← x + v × Δt [الخطوة 2: تحديث الموضع من السرعة الجديدة] q ← normalize(q + ½ × ω⊗q × Δt) [الخطوة 3: تحديث الدوران]

تكامل الرباعي (Quaternion Integration)

function integrateQuaternion(q, omega, dt) {
  // ω كـ quaternion نقي
  wq.set(omega.x, omega.y, omega.z, 0);
  // المعادلة: dq/dt = ½ × (ω ⊗ q)
  dq = wq × q;
  q.x += 0.5 * dt * dq.x;
  q.y += 0.5 * dt * dq.y;
  q.z += 0.5 * dt * dq.z;
  q.w += 0.5 * dt * dq.w;
  q.normalize(); // ضروري للحفاظ على الطول = 1
}

4. PhysicsEngine.js — محرك العالم

src/physics/PhysicsEngine.js

هذا الكلاس هو "المدير" — يُنسّق كل مكونات الفيزياء ويُقدّم الزمن بخطوات ثابتة.

الخطوة الزمنية الثابتة (Fixed Timestep)

Δt_ثابت = 1/120 ثانية (مستقل عن FPS) المتراكم (Accumulator) يحتفظ بالفرق بين وقت الإطار ووقت الفيزياء 
step(frameDt) {
  this.accumulator += Math.min(frameDt, 0.1); // تحديد أقصى للتراكم

  while (accumulator >= dt && n < maxSubSteps) {
    this._subStep(dt);    // خطوة فيزياء كاملة
    accumulator -= dt;
    n++;
  }

  // إذا وصلنا للحد الأقصى → أفرغ التراكم لمنع "حلزون الموت"
  if (n >= maxSubSteps) accumulator = 0;
}
"حلزون الموت" (Spiral of Death): إذا كانت الفيزياء تأخذ وقتاً أكبر من الإطار، ستتراكم الخطوات إلى ما لا نهاية. الحل: تحديد الحد الأقصى وإفراغ التراكم.

ترتيب الخطوة الفرعية

1
القوى الخارجية: الجاذبية → تُضاف لكل الأجسام. مقاومة الهواء (Drag) → للكرة فقط.
2
توليد جهات الاتصال: CollisionSystem.generate() يُنشئ قائمة التصادمات الفعلية.
3
حل النبضات: CollisionSystem.solve() يُطبّق النبضات على السرعات.
4
تكامل الموضع: السرعات الجديدة → مواضع جديدة.
5
تحديث النوم: الأجسام الساكنة تُوضع في وضع النوم.

مقاومة الهواء (Aerodynamic Drag)

F_drag = ½ × ρ_هواء × v² × Cd × A حيث: ρ_هواء = 1.2 kg/m³ Cd = 0.47 (كرة كروية) A = π × R² (مساحة المقطع) تأثير: Δv = -F/m × Δt (في اتجاه معاكس للحركة)

5. BowlingPhysicsModel.js — المعادلات التحليلية

src/physics/BowlingPhysicsModel.js

هذا الملف يُطبّق المعادلات المشتقة من الدراسة الفيزيائية. يُستخدم فقط للتنبؤ وعرض القيم في HUD — ليس للمحاكاة الفعلية.

المراحل الثلاث للكرة

المرحلةالوصفالشرط
الانزلاق (Skid)الكرة تنزلق بدون دوران كاملv ≠ ω × R
الانتقالالاحتكاك يُسرّع الدوران ويُبطئ الحركةجارٍ
التدحرج النقي (Roll)لا انزلاق، v = ω × Rv = ω × R

المعادلات التحليلية أثناء الانزلاق

تسارع مركز الكتلة: a = -μk × g تسارع زاوي: α = (5/2) × μk × g / R زمن التدحرج: t_roll = (2/7) × V₀ / (μk × g) سرعة التدحرج: V_roll = (5/7) × V₀ المسافة حتى التدحرج: D = (12/49) × V₀² / (μk × g)

التحقق من الدراسة (V₀=8 m/s, μ=0.15)

الكميةالمعادلةالنتيجة النظريةالمحرك
t_roll(2/7)×8/(0.15×9.81)1.553 s1.550 s ✅
V_roll(5/7)×85.714 m/s5.719 m/s ✅
D(12/49)×8²/(0.15×9.81)10.651 m10.623 m ✅

تصادم الكرة بالدبوس (1D)

حفظ الزخم + معامل الارتداد: Vb2 = ((mb - e×mp) / (mb + mp)) × Vb1 [سرعة الكرة بعد] Vp1 = (mb×(1+e) / (mb + mp)) × Vb1 [سرعة الدبوس بعد] حيث: mb=7kg, mp=1.55kg, e=0.30

6. CollisionSystem.js — نظام الاصطدام

src/collision/CollisionSystem.js

يُدير كل اكتشاف وحل الاصطدامات في المشروع. ثلاث مراحل:

مرحلة الاكتشاف السريع — Broad Phase (AABB)

// نُنشئ صندوقاً محيطاً (AABB) لكل جسم
this._ballAABB.setFromCenterRadius(ball.position, ball.radius);
this._pinAABB[i].setFromCapsule(pin.worldA, pin.worldB, pin.capsuleRadius);

// نتحقق فقط إذا كان هناك تداخل في الصناديق
if (!ballAABB.overlaps(pinAABB[i])) continue; // نتخطى إذا لا تداخل
مع 1 كرة + 10 دبابيس الفائدة محدودة، لكن البنية موجودة لتوسيع المشروع مستقبلاً.

مرحلة الاكتشاف الدقيق — Narrow Phase

الزوجالشكل الهندسيالدالة
كرة ↔ دبوسكرة ↔ كبسولةsphereVsCapsule()
دبوس ↔ دبوسكبسولة ↔ كبسولةcapsuleVsCapsule()
جسم ↔ عالمكبسولة/كرة ↔ أرضيةlane.collideBody()

حل النبضات — Sequential Impulses

solve(dt) {
  for (c of contacts) c.prepare(dt);  // حساب العوامل المسبقة

  // نُكرر N مرة (solverIterations = 12) لزيادة الدقة
  for (let it = 0; it < 12; it++) {
    for (c of contacts) c.solve();  // حل كل تصادم
  }
}
لماذا التكرار؟ مع تصادمات متعددة متزامنة (مثل دبوس يُصطدم بدبوسين معاً)، التكرار يُضمن حل جميع القيود بشكل صحيح نسبياً — كلما زاد العدد، زادت الدقة وزاد الوقت المستهلك.

نظام انتشار التأثير (Domino Cascade)

function _pinVsPin(p1, p2) {
  // دبوس متحرك يصطدم بدبوس نائم
  if (p1.body.sleeping) p1.body.wake(); // إيقاظ الدبوس الأول
  if (p2.body.sleeping) p2.body.wake(); // إيقاظ الدبوس المُصطدَم
  // هذا هو ما يُسبب تساقط الدبابيس بالتسلسل
}

7. Shapes.js — الأشكال والقيود

src/collision/Shapes.js

قيد نقطة الاتصال (Contact Constraint)

هذا هو قلب كل اصطدام في المشروع. يُحل بمعادلتين: الاتجاه العمودي (لمنع التداخل) والاحتكاك (ليحاكي الانزلاق والتدحرج):

السرعة النسبية عند نقطة الاتصال: v_rel = (v_B + ω_B × r_B) - (v_A + ω_A × r_A) النبضة العمودية (لمنع التداخل + الارتداد): Jn = -(v_rel · n)(1+e) / kn + بومغارت × (اختراق/Δt) kn = 1/mA + 1/mB + n·[I⁻¹A(rA×n)]×rA + n·[I⁻¹B(rB×n)]×rB نبضة الاحتكاك (Coulomb): Jt = -(v_rel · t) / kt مقيّدة بـ |Jt| ≤ μ × Jn
كيف يُسبب هذا ظاهرة Hook؟ عند إطلاق الكرة بدوران جانبي (ω_z)، سرعة نقطة الاتصال لها مركّب جانبي. نبضة الاحتكاك تُعاكسه، مما يُميل الكرة جانباً. في منطقة الزيت (μ=0.03) التأثير ضعيف، في المنطقة الجافة (μ=0.15) يقوى فجأة — هذا هو الـ Hook!
